# 条件图颜色残留：开发小批（出图前写定，Claude，2026-11-26）

**为什么做。** 工作台流程第一次在真实 GPU 上出图（环境核对的 3 张，2 个种子）。同一请求出两次逐像素相同，主机没问题；但两个种子的图上都有条件图的颜色：机臂上有蓝色条纹，电机里发红。条件图是黑底、红点、蓝线，文字里写着“red dots mark motor centres, blue lines mark frame links”。量了一下：明显发蓝的像素占全图 0.83% 和 0.76%（条件图自己的蓝线是 0.39%），基准状态要的是银灰机身、白背景，本不该有蓝色。这是知条件的观察，不是判读。

**对蓝图。** 这是工具在冻结前的缺陷修正，属于“真机验收”这一道门（现状总表第二节）；不是新的研究问题，结果只在 5.1.1（出图条件）里交代一句、在工作台复核记录里留档。设计场次、第 4 章案例和各批 RQ2 请求用的都是这同一条流程，颜色残留会进到每一张图里，所以先修，再跑登记的各批。

## 怎么选（出图前写定）

- **残留**用程序量，不用人看：一张图里“明显发蓝”的像素（B>110 且 B−R>45 且 B−G>20）占全图 0.10% 以上，或“明显发红”的像素（R>110 且 R−G>60 且 R−B>60）占 0.05% 以上，记这张“有残留”。阈值是看了环境核对那 3 张以后定的（0.76%—0.83%），所以这一条是事后定的，照实写。
- **不能变坏的**（Claude 知条件地看，记下来，不计入任何研究分母）：四个电机、四根机臂都在，是 X 形布局，是一件完整的产品。
- **规则：** 选“有残留”张数最少的做法；一样多时选改动小的（V1 先于 V2）。选出的做法要 4 张都满足“不能变坏的”，否则退到下一个。V1、V2 的残留张数都不少于 V0 时，流程不改，残留作为这条流程的一个已知问题照实报告。
- 选出的做法写进工作台（改版本号），各批请求重新从工作台取出，再做一次环境核对，然后才跑登记的各批。

这 12 张是开发图，不进任何正式分母。
