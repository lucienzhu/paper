# 工作台出图条件：各批 GPU 请求从工作台本身取出（Claude，2026-11-26）

**为什么有这一套。** 设计者在场次里用的是工作台。RQ2 的各批如果用另一套文字、另一张条件图，量的就不是设计实际走的那条通路，这正是 11 月 17 日审稿指出的问题。2026-11-26 核对旧的 GPU 日请求模板和工作台实际发出的请求，有三处不同：

| | 旧 GPU 日模板 | 工作台 |
| --- | --- | --- |
| 负向词 | 四旋 21 个词、六旋 15 个词 | 原为 10 个词 |
| 文字 | 整段写好的简报，只换造型句 | 逐句编译：任务与视图、布局数值、条件图读法、桨、机臂宽厚、机身包络、造型句、相机、起落架、色材、呈现 |
| 条件图 | 另画的点线图 | 工作台自己画的布局条件图（黑底、红点、蓝线） |

执行图（节点、步数 40、引导强度 3、euler、simple、三份权重）两边本来就相同。

**现在的规矩。**

1. **负向词统一为 15 个词**：工作台原有的 10 个，加 5 个桨叶词；不加相机位置词（那是设计选择）。这一份写在工作台里（`prototypes/drone-configurator/scripts/image-jobs.mjs` 的 `comfyDefaults`，工作台 4.5.3），各批从那里取，不另抄（2026-11-26 晚先在 4.5.2 上取过一次；真机上发现条件图的颜色会进到产品上，4.5.3 去掉了文字里的颜色词，请求随后从 4.5.3 重新取出，出图用的都是 4.5.3 的）。
2. **各批的请求从工作台取出**。`capture.mjs` 给工作台写入登记的参数取值，让它照常编译文字、画条件图、组执行图，把它实际发给出图服务的那一份原样记下。取出时逐项核对：发出的文字就是工作台冻结的那一段；条件图就是工作台冻结的那一张；执行图就是工作台的 `comfyGraph`；冻结的规格里各项就是登记的取值。出图服务由软件夹具应答，不调用模型。
3. **各批只盖种子和请求号**（`wbgraph.py`）。工作台的种子由轮次编号算出，批次要用登记的种子，所以走请求管线；种子、保存前缀、输入图的文件名以外，一个字不改。
4. **提交前逐份核对**。`check.mjs` 把每份请求与工作台的 `comfyGraph` 逐项比，负向词与工作台现行的那一份逐字比。事先登记的偏离要在命令里写明（换一个负向词，或控制分支的请求），否则不过。

## 文件

| 文件 | 做什么 |
| --- | --- |
| [capture.mjs](capture.mjs) | 从工作台取请求。先在 `prototypes/drone-configurator` 里 `npm run build`，再 `node experiments/workbench-graph/capture.mjs <状态表> <输出目录>` |
| [wbgraph.py](wbgraph.py) | 读取出的记录，盖种子和请求号，把条件图登记进[输入白名单](../approved-inputs.json) |
| [check.mjs](check.mjs) | `node experiments/workbench-graph/check.mjs <请求目录> [--swap 前缀:词=词] [--control 前缀]` |

## 限度

- 取出用的是本机 Chrome。条件图是浏览器画的，换一个浏览器内核，抗锯齿可能差几个像素；各批用的是这里取出并登记了摘要的那一张。
- 工作台只做日常航拍四旋和农业植保六旋两个任务（作者 11 月 23 日定）。八旋和共轴的请求走请求管线，文字用工作台同一个编译函数能写出的句子，见 H5 的登记。
