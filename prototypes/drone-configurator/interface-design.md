# 界面设计说明

## 4.0（2026-11-22）

作者试用 3.6 后要求整体重想，不做局部修补。作者看过[提案第二稿](https://claude.ai/artifact/HvGGydakNZmo9bgtmLbyBD)后同意方向，补充了几条决定：对照组也可以和 AI 对话，图像模型仍是固定的 Qwen，不做 AI 自动评图，节点怎样分请再比较。下面写这一版的做法和理由。

### 一、3.6 的问题

- 画布里装的仍是一个配置器：一张造型卡装了五个页签、二十多项参数；“另开方向”复制整份规格；改了参数，已经生成的图不提示自己过时。
- AI 站在旁边：写下目标后只给一张证据卡；“不要像玩具”这类说法没有回应；设计对话是另一个页签。
- 生成之后没有路往回走：看出“机身太长”，无法把这个判断送回机身那一步。
- 控件看不懂、信息太密：“标注、视野、透视”不说明用途；参数带英文小标题；日常航拍四旋任务也平铺三旋、八旋和共轴。
- 颜色没有含义：墨绿同时用于按钮、选中、标签和状态。
- 研究价值看不见：依据、来源、冻结输入、取舍都记了，却收在“研究详情与导出”里。

### 二、节点怎么分

后端怎样组装请求，不决定节点的边界。条件图只画机架（电机轴心和机臂连线），桨径、机身、细节和色材都以文字进入请求。上一稿以“机架和动力一起生成条件图”为由把两者合成“布局”，这个理由不成立。这一版按设计过程比较了五种分法：

| 分法 | 合不合设计者的推进次序 | 牵连是否都指向上游 | 分叉的粒度 | 画布负担 |
| --- | --- | --- | --- | --- |
| 按部件：机架、动力、机身、起落架、配件 | 弱，按零件清单排；起落架在顶视里几乎看不见却占一步 | 否，臂根放在机架里却取决于机身 | 细，但起落架、配件很少单独试 | 5 个 |
| 上一稿按阶段：布局、机身、部件、色材 | 较好 | 是 | 粗，只想换桨也得分叉整个布局 | 4 个 |
| 按感知层级：整体比例、主体形态、连接细节、色材 | 好，由整体到局部 | 部分，机身被拆进两层 | 按感受试，合语义 | 4 个 |
| 原子模块加编组 | 看设计者怎么编 | 看编法，容易乱 | 任意 | 最多 |
| **逐层搭建：机架 → 动力 → 机身 → 细节 → 色材** | 好，骨架、加桨、加机身、加细节、上色，和画草图的次序一样 | 是，每一层只受上游约束 | 每一层都能单独分叉，上游共用 | 5 个，靠紧凑卡片和整条收起压住 |

采用逐层搭建，理由有四条：

- **它就是设计展开的样子。** 每个节点除了管自己的决定，还画出到这一层为止的累积顶视图。沿着链从左往右看，就是方案一层层长出来的过程。部件化的做法要解决“分开改、整体还要连贯”（A02 把部件预览串回整体方案，B09 比较了先整体后拆件与按部件组合）；累积显示让设计者在任何一层都看得到整体。
- **顺序由牵连关系定。** 桨盘不重叠只看机架，机身离桨盘的间隙看动力，臂根和相机看机身。改上游时下游被告知，不会出现下游反过来破坏上游的回路。这对应设计结构矩阵把有反馈的任务排成下三角的思路，以及 Alexander、Simon 说的“内部紧、外部松”。这三处经典理论库里没有原件，论文要引用时先补。
- **每一层有自己的研究身份。** W/L 在机架（由条件图控制、回量），桨径比在动力，机身宽与轴距之比、机身长宽比在机身；细节和色材是判读核对的造型档位（RQ2b）。一个节点的改动、它在生成里怎样起作用、出图后拿什么核对，三件事对得上。
- **从感知层级借一样东西。** 意图里的语义目标标出它作用在哪几层：“紧凑”指向机身和动力，“整体”指向细节和机身，“简洁”指向机身的顶盖分件和细节，“低调或醒目”指向色材。

### 三、AI 在每一步

AI 起草，设计者拍板。文献里中等自动化在负荷与协作之间最平衡（L072），这里取的就是这一档。

| 哪一步 | AI 做什么 | 设计者做什么 |
| --- | --- | --- |
| 意图 | 读出场景、观察状态、造型目标，配上用户原话；“不要像拼起来的”这类说法给出几种理解 | 逐条采纳或不要；补充一句时已确认的不作废 |
| 方向 | 按意图提几组跨层的改动 | 放上画布成为一条方向，或不要 |
| 某一层 | 把“再紧凑一点”变成这一层的参数建议，标明依据强弱；超出这一层时指出该去哪一层 | 照此修正、开分支试、直接改、不用 |
| 候选 | 把“机身短一点，其他别动”变成只动相关层的修改，其余层记为保持不动 | 确认后生成；或把问题送回某一层 |
| 自由提示那一场 | 和设计者聊想法、起草提示词；看不到证据和参数 | 改好或直接用，再生成 |

不做 AI 自动评图。比较和取舍完全由设计者做。

### 四、证据强弱怎样说

档位由证据登记（[registry.mjs](src/design/evidence/registry.mjs)）决定，不由模型决定：取建议所引条目里与改动字段相关的最强一条；没有引用的一律算设计假设。表达不靠警告，靠三样东西：

- **字的语气。** 给模型的提示要求按档位措辞：统计相关不能说成“改了就会”，要说“往往”“值得试”；没有依据的想法可以提，但不引用条目，算设计假设。接上真实模型后要核对它是否照做；规则回退的答复按这个写法写。
- **三格标记。** 三格实心是已验证，两格是统计相关，一格是设计假设。
- **主按钮。** 只有已验证的建议主按钮是「照此修正」；统计相关和设计假设的主按钮是「开一个分支试试」，生成后放在一起比。拿不准的规律因此变成一个可以比较的分支，而不是一条规则。

两条依据方向相反时（例如护圈让整机读起来更大，而相关结果在去掉护圈机型后变弱），两边都列出来。比较时写下的观察记为设计者对这个方案的判断，不算研究数据。用户原话单独显示，它支撑意图，不支撑比例。

### 五、画布与面板

```
┌ 顶栏：方向切换 · 登记条件 · 出图后端 · 文字模型 · 撤销/重做 · 研究记录与导出 · 旧版 ┐
│ [意图]─▶[机架]─▶[动力]─▶[机身]─▶[细节]─▶[色材]─▶[生成]─▶[候选][候选]─▶[比较] │ 右侧面板 │
│                    └┄┄┄▶[机身′]─▶[细节]─▶[色材]─▶[生成]─▶[候选]          │ 随选中   │
│ 共用的上游只画一次；不在编辑的方向变淡；可以整条收起                     │ 的节点变 │
│            ┌ 下方输入框：对选中的那一步说 ┐                              │          │
└────────────────────────────────────────────────────────────────────────┘
```

- 分叉复制这一层和下游。共用的层上可以「只改这条方向」（拿到自己的一份），也可以「用另一条方向的这一层」。
- 生成节点把这一轮冻结时的规格和当前规格比，上游改过就标“已过时”，列出改了哪几项。
- 修改轮从父图那张候选连出，看得出一步步怎样改过来。
- 机架被登记条件锁定时，控件变灰、输入框停用，AI 也不提这一层的建议。
- 点空白处或按 Esc 回到总览。总览给出按规则算出的下一步（不调用模型）、各条方向的进度，以及主持人用的场次设置。

### 六、视觉系统：石墨

- 底色是中性的纸白（#f2f3f5）和石墨（#16181b、#4a5058、#848a93），不用品牌色。
- 颜色只表示意义：轴心橙（#e8590c）是可拖动的电机轴心；建议紫（#6b55d1）是 AI 的建议和还没建立的分支；琥珀是需要处理（过时、待处理）；绿是核对通过和已保留。
- 选中用石墨描边加抬起，不用彩色。
- 字体用系统字体，离线可用；间距取 4 的倍数；节点圆角 10，控件 7，标签全圆。

### 4.1 的修订（2026-11-22，Codex 评审之后）

- 分叉以后，面板跟到新方向的同一层；以前面板停在原方向，接着的改动会落回原方向。
- 在一张旧候选上改：从这张图冻结时的规格出发，另开一条方向，只加这次的改动。以前改动加在方向“现在”的规格上，旧图之后改过的部分会混进来，没要求改的就保不住。
- 节点可以单个拖动，“整理”排回按链对齐的位置；位置是界面的事，不进撤销历史。
- 色材可以自定义：任意颜色、更多表面处理、一栏原样写进文字的补充说明。
- 一轮等太久时给出“重新取回”和“放弃这一轮”。
- 两种方式的取舍都能写理由、定终稿；自由提示那一场也能打开研究记录；一场的材料打成一个 ZIP。
- 用途不在两个场景里时先问设计者按哪一个做。

### 4.2 的修订（2026-11-23，对照蓝图与论文研究之后）

- 起点按主实验：主持人按委托开一场，任务、委托原文和 C2 机架一起定下，两种方式看到同一段委托；工作台只做日常航拍四旋和植保六旋两个任务，机架层只给本任务的构型。八旋、共轴等迁移检验走 GPU 请求管线，不在工作台里做。
- 场次是记录的单位：每一轮、每条事件、对话、建议都写下属于哪一场；同一个项目里换方式就是另起一场，每一场导出自己的 ZIP，标签与内容一致。
- 植保六旋加药箱和喷洒部件，句子用已出过图的原文，选项旁写明出过多少图；起始值对齐既有 39 张。
- 机身间距按画出的外形量：核对和示意图用同一份圆角定义，不再对 C2 起点亮假警告。
- 已经有决定时换任务要确认并另开项目；AI 读出的任务不同只问不换。
- 文字模型锁定 MiniMax-M3.1-Flash，日志和标签写明服务主机。见[复核记录](review/20261123-workbench-4.2/README.md)。

### 七、还没有验证的

- 接上真实文字模型后的表现：是否守住输出格式、建议的质量、等待时长。现在的检查全部用规则回退。
- Qwen 后端仍没有对真实 GPU 主机测过。
- 五层加意图和生成，一条链七张卡，作者试用后才知道负担是否可接受。
- 窄屏下画布在上、面板在下，只做了基本适配。

## 3.4 版（2026-11-19）

2026-11-19，第四轮。这一轮把工作台改成一块画布：设计的每一步都是画布上的一张卡片，在卡片上直接做，右侧面板跟着所选的那一步变化。下面说明为什么这样改、每一步长什么样、依据是什么，以及还没有验证的地方。

### 一、上一版的问题

上一版有四个页面：画布、目标、参数、候选图。画布上只有两张展示用的卡片，不能在上面加步骤；写目标、调参数、生成都要离开画布去另一个页面，做完之后画布才把结果画成一张关系图。作者试用后的判断是：这反直觉，步骤被拆散了，画布只是事后的流程图；同时流程被排成固定的顺序，设计显得僵硬。

### 二、依据

[画布式工作流拆解](../../planning/workbench-handoff/literature/画布式工作流拆解.md)读了三项把同一后端接到不同界面上比较的研究，结论可以直接用：

- 步骤应当是画布上的对象。设计者选中一个对象、点一个直接动作，系统把新对象接在后面并自动连线。在 Workflow-Net 的九人比较里，这种做法的创造力支持、可用性和负荷三项都好于手工接线的节点图和只靠对话的界面；手工接线把人锁在一条线上，对话到细化阶段失控。
- 节点里可以直接干活。DesignTrace 的每个节点内嵌一块可编辑的画布，并保存自己的历史。
- 参数放在随所选节点变化的侧栏里。InspirationGraph 有意不像 ComfyUI 那样把参数塞进节点，以保持画布清楚。
- 对话适合开头的发散，不能是唯一入口；过程历史要自动留下，不要让设计者手工维护。

作者设想的布局是“画布，加右侧的组件面板或对话界面，随每一步变化”。这与上面几条一致。

### 三、一块画布

```
┌ 顶栏：我的项目 / B2 案例 · 撤销 · 显示留档 · 研究详情与导出 ─────────────┐
│                                                        │ 右侧面板          │
│  [依据]─▶[目标]─▶[造型]─▶[生成]─▶[候选图]─▶[取舍]        │ 这一步 | 设计对话  │
│                    │                 └─▶[生成]─▶[候选图] │                   │
│          [目标]─▶[造型]（另一个方向）    [参考图] [便签]   │ 随所选卡片变化     │
│                                                        │                   │
│        底部工具条：目标 · 参考图 · 便签 · 新方向 · 生成效果图               │
└────────────────────────────────────────────────────────────────────────┘
```

**卡片就是步骤，在卡片上直接做。**

| 卡片 | 在卡片上能做什么 | 选中后右侧面板给出 | 对应论文 |
| --- | --- | --- | --- |
| 目标 | 直接写一句想要的变化，回车保存 | 按话题和使用状态查到的用户原话，采用、驳回或只存自定目标；用途与构型；外观偏好词对；全部公开短引的检索 | 3.2 需求资料，3.3.1 意图与词对 |
| 用户依据 | 一张公开短引，连着它支持的目标 | 原话、对象、适用限制、来源编号 | 3.2 |
| 造型 | 顶视图就在卡片里：拖橙色轴心改轴距和横纵比，点机身或桨盘出现可拖的手柄；切换顶视、条件图、侧视；下方是三个比例读数 | 五个部件页签的参数；布局空间图、设计提示、参考机型；撤销与叠加层开关 | 3.4 参数与条件图，4.1.2 部件 |
| 参考图 | 上传、拖入，或从 B2 案例引用 | 以此图生成、对照、移除 | 3.5.1 条件输入 |
| 生成 | 待提交时是虚线卡片，点卡片上的「生成」才提交 | 将要提交的三样内容：布局条件图、由造型和目标编译的文字、参考图；这一轮想改变什么 | 3.3.3 人工确认，3.5.1 |
| 候选图 | 回图自动接在那一轮后面 | 保留、以此图继续生成、图片对照；驳回与回选在完整记录里 | 4.2 方案比较与取舍 |
| 取舍、便签 | 取舍自动留下；便签随手写 | 来源与关系 | 4.2 |

**怎样加一步。** 四种方式做同一件事，都不需要手工接线：

1. 选中一张卡片，它上方出现接下来能做的事。造型卡片给出「生成效果图」「另开方向」「存为版本」，候选图给出「保留」「以此图继续」「对照」，参考图给出「以此图生成」。点一下，新卡片出现在它右边并连好线。
2. 底部工具条：目标、参考图、便签、新方向、生成效果图。
3. 双击画布空白处，在那个位置添加便签、参考图、新方向或生成步骤；把图片文件直接拖进画布就是一张参考图。
4. 从卡片右侧的加号拖一条线到另一张卡片。把图拖到「生成」卡片上，这张图就随那一轮提交；拖到其他卡片上，记为设计上的参考关系。

**右侧面板随所选步骤变化。** 没有选中任何卡片时，面板列出目标、造型、生成、取舍四项的进度，并标出下一步；这是按规则算出的提示，没有调用模型。面板的另一个页签是设计对话，围绕当前方向和正在看的部件：只查依据不需要模型账号，查到的原句可以放到画布上；模型给出的机身宽度建议先在造型卡片上以虚线预览，由设计者决定应用、驳回或撤销。

**放上去的也能拿下来。** 选中便签、参考图或待提交的生成步骤，按 Delete 或点「移除」；设计者自己放上画布的证据卡可以「从画布移开」，随目标采纳的依据要在目标面板里撤销。已经提交的生成轮次、候选图和取舍是记录，不能删除。

**不规定顺序。** 可以先写目标，也可以先拖造型、先放一张参考图。几个方向并排在画布上，点哪个方向的卡片就编辑哪个；每个方向有自己的目标、造型和生成记录。造型项（臂根、材料、机身轮廓、顶盖、相机安装、主色、表面）仍然可以不指定，不指定就不写进提交的文字。

**卡片不乱跑。** 第一次打开时按来源关系排成列：依据 → 目标 → 造型 → 生成 → 候选 → 取舍。之后每张新卡片只在出现时安放一次（接在来源右边，新方向排在原方向正下方），已有的卡片和设计者拖过的位置都不动。左下角的「整理」可以按来源关系重排全部卡片。

### 四、研究记录放在哪里

设计者的主线上只有上表这些卡片。每一轮冻结的规格和布局条件图是研究留档，默认收起；点顶栏的「显示留档」在同一块画布上展开，连线标注冻结输入和实际使用的父图。「研究详情与导出」是画布之外唯一的一层，放逐句的提示词来源、规格卡、导出、全部轮次的回执与取舍、历史回放和旧版 ComfyUI 回执导入。这样做是按[双机交接](../../planning/workbench-handoff/README.md)里的要求：减少主流程的操作负担，把来源、图像输入、规格版本与模型回执放在可展开的研究详情里，同时保留可查的原句、父图、采纳、驳回和撤销。

每一轮生成仍然记录实际提交的文字、条件图摘要、父图或参考图、服务回执和候选原图摘要。新加的一种输入是画布上的参考图：提交的文字用单独一句说明“第二张图是设计者选的外观参考”，记录里的父图编号指向画布上那张参考图；上传的 JPEG 或 WebP 在浏览器里转成 PNG 再提交。

### 五、保留下来的设计

- 轴心几何、条件图、坐标和提示词布局句仍出自同一组数（`computeLayout`）。
- 四个比例读数旁标出真实机型的范围；设计提示仍是相机视野、桨盘重叠、桨与机身间隙三条俯视近似。
- 目标用语义检索找原话：按使用任务、构型、话题和观察状态筛选，场景不符时可以只存自定目标，驳回要写理由。
- 每一步都能撤销；改过的参数可单独重置；保存的版本不可变，可以从任一版本继续。
- 换了使用任务或构型族时，已确认的目标仍需重新确认。原来的文字留在目标卡片上作为未保存的草稿，按一下「确认目标」即可，不会凭空消失。
- 视觉上仍是浅色点阵画布、白色卡片、墨绿作强调、信号橙只用于电机轴心。

### 六、窄屏

宽度小于 900 像素时，面板移到画布下方，画布随之缩小并把选中的卡片缩到看得见；底部工具条只留图标。手机上可以查看和做简单修改，拖动造型建议在平板或桌面上做。

### 七、还没有验证的

- 这一轮只做了软件走查：`npm run walkthrough:canvas` 在隔离的浏览器里把上面每一步都做了一遍，图像作业由软件夹具应答。没有调用模型，没有作者试用，也没有外部设计者参与。界面是否更直觉、是否更省时，要由作者预试和配对试验回答。
- 文献支持的是“步骤放在画布上、直接操作、自动连线、侧栏随所选对象变化”这一选择；原研究的任务是椅子、灯具、杯子一类，各九人。不能据此预设在多旋翼任务上的效果。
- 参考图作为生成输入没有对真实模型测过。
- 这套步骤换一种产品时，需要替换的是评论语料与话题标注、参数与几何规则、提示词编译三样数据。这是结构上的判断，没有在第二种产品上试过。
- 没有做的：在画布上直接圈选候选图的局部再改；多张候选的批量比较；按相邻夹角输入布局；折叠状态。
